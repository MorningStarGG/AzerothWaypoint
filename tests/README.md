Open the addon folder in VS Code for WoW development. To edit fixtures, open the tests folder in its own window with `code -n tests` from the addon root. Each window runs its own Lua language server. Opening a mock inside the addon window can give a live addon function the mock's signature even when the mock is excluded from background indexing.

The tests folder uses standalone Lua 5.1. Opening a fixture checks that file. Each fixture executes in a fresh Lua process, and different fixtures can assign different functions to the same global.

Run `python tests/check_fixtures.py` to check every fixture and helper with LuaLS. It checks each file in its own workspace and exits with a failure on any warning or error. To check one file with an installed editor server, use `python tests/check_fixtures.py --server <executable> tests/mapzeroth_backend_test.lua`.

Run `python tests/check_addon.py` for the addon-wide LuaLS warning and error check. If LuaLS is installed through VS Code, pass the path to its server executable as the argument. This uses the WoW API extension's local workspace settings and the repository's addon analysis scope.

From the addon directory, run `python tests/run.py --suite standalone` with Python 3 and Lua 5.1 on PATH. Each fixture runs in a fresh Lua process. A fixture that requests installed addon source counts as skipped in this suite.

For the full suite, run `python tests/run.py`. A checkout outside the game needs `AWP_RETAIL_ADDONS` and `AWP_FOREVER_ADDONS` set to the two clients' Interface/AddOns directories. The full suite also runs the GW2_UI appearance fixture with the Retail argument in addition to its default Forever run.
